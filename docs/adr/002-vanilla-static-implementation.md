# ADR-002：v1 使用原生 Web 技术与 ES Modules

## 状态

已接受。

## 背景

v1 已确认采用纯前端静态应用。M1 需要确定前端框架、编辑器组件和构建方式。候选方案包括：

1. 原生 Web 技术与 ES Modules。
2. React / Vue 等前端框架加构建工具。
3. CodeMirror / Monaco 等编辑器组件。

## 决策

v1 采用原生 Web 技术与 ES Modules：

1. 不引入前端框架。
2. 不引入构建工具和第三方运行时依赖。
3. v1 编辑器使用原生 `textarea` 和等宽字体。
4. 工具逻辑放在独立 ES Module，便于浏览器和 Node 测试复用。
5. 正则匹配放入 Web Worker，主线程负责超时和取消。

## 理由

1. v1 交互以表单、文本转换和结果展示为主，状态复杂度有限。
2. 无第三方依赖可以降低首屏体积，便于静态托管。
3. 无构建链路可以降低维护成本，便于快速验证。
4. Node 可以直接导入纯逻辑模块执行自动化测试。

## 后果

### 正面影响

1. 首屏性能更好。
2. 代码结构清晰，隐私边界明确。
3. 测试不依赖浏览器环境。
4. 任何静态服务器均可部署。

### 负面影响

1. 原生 `textarea` 不提供高级编辑体验。
2. UI 状态管理需要手写，代码组织要求更高。
3. 后续功能复杂后可能需要框架迁移。

### 重新评估触发条件

当满足以下任一条件时，重新评估引入框架或编辑器组件：

1. UI 状态复杂度明显超过原生 DOM 管理能力。
2. 需要复杂 JSON 树、Diff、折叠和编辑能力。
3. 需要协同编辑或完整 IDE 体验。
4. 组件复用成本显著影响迭代效率。
