# Online DevTools 开发者工具箱设计文档

## 1. 背景

开发者在日常工作中经常需要格式化 JSON、编解码 Base64、转换时间戳、调试正则表达式或解释 Cron 表达式。这些操作高频、轻量、对隐私敏感，通常不需要完整后端服务，也不应该要求用户登录或安装本地工具。

Online DevTools 的定位从早期的“在线代码运行 playground”调整为“开发者常用工具箱”。v1 聚焦五个高频工具，优先做到打开即用、结果可靠、可分享、可复制。

## 2. 目标

### v1 目标

1. 提供五类核心工具：
   - JSON 解析与格式化
   - Base64 编解码
   - 时间戳与时间转换
   - 正则表达式测试
   - Cron 表达式解析
2. 无需登录即可使用。
3. 数据处理默认在浏览器本地完成，不上传服务器。
4. 支持复制输入、输出和常用结果。
5. 支持通过 URL hash 保存当前工具状态。
6. 支持通过分享链接恢复完整输入与参数。
7. 支持桌面端与移动端基础可用布局。
8. 提供清晰、可操作的错误提示。

### v2 目标

1. 分批补齐开发者高频工具：
   - URL 编解码与解析
   - UUID 生成器
   - Hash 工具
   - HTTP 状态码速查
   - MIME Type 速查
   - HTML Entity 编解码
   - 颜色转换器
   - 进制与位运算
   - 文本处理工具
   - Mock 数据生成
2. 支持联调排查工具：
   - JWT 解析
   - 文本与 JSON Diff
   - 乱码修复与字符编码转换
3. 支持数据格式转换工具：
   - YAML ↔ JSON
   - CSV ↔ JSON
   - TOML ↔ JSON
   - XML 格式化
   - SQL 格式化
   - Markdown / HTML 转换
4. 支持本地收藏与最近使用记录。
5. 支持 PWA 离线使用。
6. 支持更多 JSON 树形查看、JSONPath、Diff 能力。
7. 支持 Quartz Cron 或更完整的 Cron 方言。

## 3. 非目标

以下内容明确不在 v1 范围内：

1. 不做在线代码运行环境。
2. 不做通用在线 IDE。
3. 不做实时协作。
4. 不做账号、团队、权限、订阅和付费。
5. 不做服务端数据存储。
6. 不承诺支持所有正则引擎方言；v1 以浏览器 JavaScript RegExp 语义为准。
7. 不承诺支持所有 Cron 方言；v1 优先支持标准五字段 Cron。

## 4. 目标用户与核心场景

### 用户

- 后端开发者：排查接口 JSON、调试 Cron 任务、转换时间戳。
- 前端开发者：处理 Base64、调试正则、格式化 JSON。
- 测试与运维人员：检查正则匹配、解释定时任务表达式。
- 技术写作者：生成可分享的示例和结果。

### 核心场景

1. **JSON 排查**：粘贴接口返回的 JSON，快速格式化并定位语法错误。
2. **编解码转换**：处理 URL、Header、Token 中的 Base64 内容。
3. **时间换算**：将日志中的 Unix 时间戳转换为可读时间，或将本地时间转换为时间戳。
4. **正则调试**：输入表达式与测试文本，查看匹配结果和分组。
5. **Cron 排查**：输入 Cron 表达式，查看执行含义和未来执行时间。
6. **状态分享**：把某个工具的输入和参数放入链接，发给同事继续排查。

## 5. 用户流程

### 5.1 首次使用

```text
打开首页
  → 看到工具入口
  → 选择目标工具
  → 输入内容并设置参数
  → 应用自动或手动执行
  → 查看结果
  → 复制结果或分享链接
```

### 5.2 打开分享链接

```text
点击分享链接
  → 应用恢复工具类型、输入内容、参数和输出区域状态
  → 自动执行解析或转换
  → 用户查看结果
```

### 5.3 错误路径

```text
输入无效 JSON / Base64 / 时间 / 正则 / Cron
  → 保持原始输入
  → 显示明确错误原因
  → 提供可操作建议
  → 不清空用户输入
```

## 6. 信息架构与导航

### 6.1 页面结构

```text
┌──────────────────────────────────────────────┐
│ Logo / 工具搜索 / 主题切换 / 帮助入口          │
├────────────┬─────────────────────────────────┤
│            │ 工具标题与简介                   │
│ 工具导航    ├─────────────────────────────────┤
│            │ 输入区 / 参数区                  │
│ JSON       ├─────────────────────────────────┤
│ Base64     │ 输出区 / 错误提示                 │
│ 时间戳      ├─────────────────────────────────┤
│ 正则        │ 操作栏：复制 / 清空 / 示例 / 分享 │
│ Cron       │                                  │
└────────────┴─────────────────────────────────┘
```

### 6.2 响应式布局

- 桌面端：左侧固定工具导航，右侧为工作区。
- 平板端：工具导航可折叠。
- 移动端：顶部工具下拉或抽屉导航，输入输出上下排列。

### 6.3 关键通用交互

1. **自动执行**
   - JSON、Base64、时间戳工具在输入变化后自动处理。
   - 正则与 Cron 输入变化后自动校验并更新结果。
   - 对较大输入使用防抖，避免频繁计算阻塞界面。

2. **复制**
   - 输入区、输出区均提供复制按钮。
   - 时间戳工具支持复制秒级时间戳、毫秒级时间戳和格式化时间。
   - 复制成功后提供短暂状态反馈。

3. **清空与示例**
   - 每个工具提供“清空”。
   - 每个工具提供至少一个可运行的示例。

4. **分享**
   - 点击“分享”生成当前工具状态 URL。
   - 状态放在 URL hash 中。
   - URL 超过安全长度时提示用户精简内容。

5. **主题**
   - 支持系统深浅色模式。
   - 用户手动选择后写入本地偏好，但不参与分享链接。

## 7. 工具设计

### 7.0 扩展工具总体设计

后续工具按四个层级组织：

1. **导航分组**
   - 常用转换：JSON、Base64、URL、时间戳、UUID、Hash、颜色、进制、文本
   - 校验调试：正则、Cron、JWT、Diff、字符编码、HTML Entity
   - 数据转换：CSV、JSON → TS、XML、SQL、Markdown、YAML、TOML、Mock
   - 速查手册：HTTP、MIME
   - 动态分组：收藏、最近使用（基于 localStorage，见 v1.4）
2. **通用工作台**
   - 输入区、参数区、输出区复用现有模式。
   - 速查类工具使用搜索 + 表格布局。
   - 转换类工具使用输入输出双栏布局。
3. **分批交付**
   - v1.1：高频通用工具
   - v1.2：联调排查工具
   - v1.3：数据格式转换
   - v1.4：高级体验与离线能力
4. **质量边界**
   - 每批工具必须包含设计、实现、自动化测试和验收记录。
   - 新工具不改变“浏览器本地处理、不上传数据”的隐私边界。

#### v1.1 工具范围

1. **URL 编解码**
   - URL encode / decode
   - Base64URL 可与标准 URL 编码区分
   - Query 参数解析与组装
   - URL 结构解析
2. **UUID 生成器**
   - UUID v4 批量生成
   - 大小写切换
   - 连字符开关
   - UUID 校验
3. **Hash 工具**
   - SHA-1 / SHA-256 / SHA-384 / SHA-512
   - 输入文本
   - 输出小写 / 大写
   - 浏览器 `crypto.subtle` 本地计算
4. **HTTP 状态码速查**
   - 1xx / 2xx / 3xx / 4xx / 5xx
   - 搜索
   - 含义、常见场景与缓存/重试语义
5. **MIME Type 速查**
   - 常见扩展名与 MIME 映射
   - 搜索

#### v1.2 工具范围

1. **JWT 解析器**
   - Header / Payload / Signature 展示
   - Base64URL 解码
   - `iat`、`exp`、`nbf` 解释
   - 过期状态提示
   - 不验证签名
2. **Diff 工具**
   - 文本行级 Diff
   - JSON 格式化后 Diff
   - 新增、删除、修改标记
3. **乱码修复与字符编码**
   - Hex ↔ Text
   - 常见乱码说明
   - UTF-8 / Latin-1 转换
4. **HTML Entity 编解码**
   - HTML encode / decode
   - 支持命名实体
   - 支持数字实体
   - 防止输出直接作为 HTML 注入

#### v1.2 交互细节

1. JWT 输入后自动解析 header、payload 和 signature。
2. JWT 时间字段 `iat`、`exp`、`nbf` 显示为可读时间，并标注是否已过期或尚未生效。
3. Diff 支持文本行级对比与 JSON 格式化后对比。
4. Diff 输出区分新增、删除、未变化，并显示差异行数。
5. 编码工具支持源格式、目标格式和错误提示。
6. HTML Entity 输出始终按文本渲染。

#### v1.3 工具范围

v1.3 按实现风险分两批交付；本节记录第一批的确认设计，第二批在实现前补充细化。

##### v1.3 第一批（数据格式与类型生成）

1. **CSV ↔ JSON**
   - CSV → JSON：第一行默认作为表头，可选无表头模式（列名 `column_1` 起）。
   - JSON → CSV：输入必须是对象数组；列名取所有对象键的并集。
   - 支持分隔符：逗号、分号、Tab、竖线。
   - 解析规则遵循 RFC 4180 常用子集：支持引号字段、双引号转义、字段内换行。
   - 嵌套对象 / 数组写入 CSV 时序列化为 JSON 字符串并加引号。
2. **JSON → TypeScript**
   - 输入合法 JSON 值，生成 `interface` 声明。
   - 数组内对象合并为一个 interface；字段缺失标记为可选（`?`）。
   - 嵌套对象生成独立 interface，形状相同时复用。
   - 根类型名可通过参数指定，默认 `Root`。
3. **XML 校验与格式化**
   - 校验基本良构性：标签配对、属性引号闭合、唯一根元素。
   - 支持处理指令、注释、CDATA、自闭合标签。
   - 格式化按选定缩进（2 空格 / 4 空格 / Tab）输出。
   - 纯文本节点保持与元素同行（如 `<a>text</a>`）。

##### v1.3 第二批（本节为确认设计）

1. **SQL 基础格式化**
   - 输入 SQL 语句，按主要关键字（SELECT / FROM / WHERE / GROUP BY / ORDER BY / LIMIT / JOIN 系列 / UNION 等）分行并缩进。
   - 字符串字面量内容不参与关键字识别。
   - 参数：大写关键字开关（默认开启）、缩进（2 空格 / 4 空格 / Tab）。
   - 边界：不支持完整 SQL 方言校验；不做语法树解析；括号内子查询保持原样缩进一层。
2. **Markdown → HTML**
   - 支持：h1–h6 标题、段落、粗体、斜体、行内代码、代码块、链接、图片、无序 / 有序列表、引用块、分隔线。
   - 输出按纯文本展示，不直接注入页面 DOM。
   - 边界：不支持表格、脚注、任务列表、HTML 内嵌块；多行列表项按单行处理。
3. **YAML ↔ JSON**（自写子集解析器，见 ADR-006）
   - 支持：2 空格缩进的嵌套映射、`- ` 序列、标量（字符串 / 整数 / 浮点数 / 布尔 / null）、单双引号字符串、行内 `[a, b]` 与 `{k: v}`（一层）、块标量 `|` 与 `|-`、整行与行尾注释。
   - 不支持（明确文档化）：锚点与别名、标签、复杂键、多文档 `---`、指令、多级嵌套行内集合、`>` 折叠标量。
   - JSON → YAML：映射 / 序列 / 标量常规输出；含特殊字符的字符串加引号。
4. **TOML ↔ JSON**（自写子集解析器，见 ADR-006）
   - 支持：`[table]`、`[[array of tables]]`、点号键、基本字符串（含转义）、字面量字符串、整数、浮点数、布尔、数组、行内表。
   - 不支持（明确文档化）：多行字符串 `"""` / `'''`、日期时间类型、本地时间。

##### v1.3 第二批状态模型

```text
sql:      { toolId, input, params: { uppercase: boolean, indent: "2" | "4" | "tab" } }
markdown: { toolId, input, params: {} }
yaml:     { toolId, input, params: { mode: "toJson" | "fromJson" } }
toml:     { toolId, input, params: { mode: "toJson" | "fromJson" } }
```

##### v1.3 第二批交互细节

1. SQL / Markdown 输入后自动格式化或转换。
2. YAML / TOML 通过方向下拉切换解析与生成。
3. 全部工具提供复制输出、清空、示例。

##### v1.3 第二批边界与错误处理

1. 输入上限沿用 1 MiB。
2. YAML 缩进不一致或行内集合未闭合时报错并定位行号。
3. TOML 表重复定义、值类型无法识别时报错并定位行号。
4. Markdown 中的 HTML 特殊字符转义后输出，防止注入。
5. 所有处理保留在浏览器本地，无网络请求。

##### v1.3 状态模型

```text
csv:      { toolId, input, params: { mode: "toJson" | "fromJson", delimiter, header: boolean } }
jsonToTs: { toolId, input, params: { rootName: string } }
xml:      { toolId, input, params: { indent: "2" | "4" | "tab" } }
```

##### v1.3 交互细节

1. 三个工具均粘贴输入后自动转换，输出区展示结果，错误区展示行号（可定位时）。
2. CSV 参数变化、XML 缩进变化立即重新处理。
3. JSON → TypeScript 的根类型名参与 URL hash 状态。
4. 全部工具提供复制输出、清空、示例。

##### v1.3 边界与错误处理

1. 输入上限沿用 `MAX_INPUT_LENGTH`（1 MiB），超限直接拒绝。
2. CSV 列数不一致时报错并定位到首个不一致行。
3. CSV 引号未闭合时报错并定位到行号。
4. JSON → CSV 输入不是对象数组时报可读错误。
5. XML 标签不配对时报错并定位到行号。
6. XML 不做 DTD / XSD / Schema 校验。
7. 所有处理保留在浏览器本地，无网络请求。

#### v1.4 工具范围

v1.4 拆分为两批：第一批实现四个新工具与体验增强（本节为确认设计，见 ADR-007）；第二批评估 JSON 树形视图 / JSONPath 与 Cron 宏 / Quartz 方言。

##### v1.4 第一批（新工具）

1. **颜色转换器**
   - 输入识别：#RGB / #RGBA / #RRGGBB / #RRGGBBAA、rgb() / rgba()、hsl() / hsla()（逗号或空格分隔）。
   - 输出 HEX / RGB(A) / HSL(A) 三种表示，带色板预览与逐项复制。
   - 相对亮度与“与白底 / 黑底对比度”按 WCAG 公式计算，并给出建议文字颜色。
   - 参数：HEX 大写开关。不支持命名颜色与百分比 RGB，页面明示。
2. **进制转换与位运算**
   - 输入：数字 A（可选进制：自动 / 2 / 8 / 10 / 16）；自动识别支持 0x / 0b / 0o 前缀，无前缀纯数字按十进制，仅含十六进制字符按十六进制。
   - 输出 A 的二进制、八进制、十进制、十六进制四种表示。
   - 位运算：AND、OR、XOR、NOT、左移、右移；全部按 64 位无符号整数（0 到 2^64-1）语义，NOT 返回 64 位补码，左移结果掩码回 64 位，移位位数 0-63。
   - 参数：数字 B、HEX 大写开关。
3. **文本处理**
   - 命名风格转换：camelCase、PascalCase、snake_case、kebab-case、CONSTANT_CASE、全大写、全小写、Title Case、Sentence case；单词拆分识别下划线 / 短横线 / 空格与驼峰边界（含连续大写缩写）。
   - 行处理：升序 / 降序排序、去重（保序）、去除行首尾空白、删除空行、行倒序、行编号。
   - 字符与换行符：字符倒序（Unicode 码点安全）、CRLF → LF、LF → CRLF。
   - 任意操作均附带统计：字符数（码点）、不含空白字符数、词数、行数、非空行数、UTF-8 字节数。
4. **Mock 数据生成**
   - 输入：JSON 对象模板（或只含一个模板元素的数组）；字符串值使用 @占位符。
   - 占位符：@cname 中文姓名、@name 英文姓名、@email、@phone（大陆手机号格式）、@integer(min,max)、@float(min,max,精度)、@boolean、@uuid(v4)、@id / @index 自增计数、@pick(a|b|c)、@string(n)、@hex(n)、@date(start,end)、@datetime(start,end)、@timestamp(start,end)、@repeat(n, 占位符)。
   - 非字符串标量原样保留；数组逐元素套用模板；@repeat 生成嵌套数组。
   - 参数：数量（1-100）、种子；填写种子时使用 xmur3 + mulberry32 确定性随机流，同种子同模板输出完全一致；留空使用 Math.random。
   - 不支持的占位符与非法参数报可读错误并列出支持列表。

##### v1.4 第一批状态模型

```text
color: { toolId, input, params: { uppercase: boolean } }
radix: { toolId, input, params: { base: "auto"|"2"|"8"|"10"|"16", operator: "none"|"and"|"or"|"xor"|"not"|"lshift"|"rshift", operand: string, uppercase: boolean } }
text:  { toolId, input, params: { action: string } }
mock:  { toolId, input, params: { count: number, seed: string } }
```

##### v1.4 第一批体验增强

1. **本地收藏与最近使用**
   - 顶栏“收藏工具”按钮收藏 / 取消收藏当前工具；收藏列表存入 localStorage（`devtools-favorites`，上限 12）。
   - 最近使用在切换工具时更新（`devtools-recent`，上限 8，导航展示前 5 且去重收藏）。
   - 导航顶部动态渲染“收藏”“最近使用”分组；两者均为空时不占位。
   - 收藏与最近使用不参与 URL 分享状态（与主题一致）。
2. **工具导航筛选**
   - 导航顶部提供筛选输入框，按工具名称与 toolId 过滤；无匹配链接的分组标题同时隐藏。
   - 快捷键 `/` 聚焦筛选框（在输入控件内时不劫持），Esc 清空并失焦。
3. **PWA 离线支持**
   - 提供 `manifest.webmanifest`（含 SVG 图标，purpose any maskable）与 Service Worker。
   - Service Worker 预缓存全部静态资源，运行时对同源 GET 采用 cache-first、网络回填；离线时回退到缓存的 index.html。
   - 缓存名带版本号（`devtools-v1-4-0`），新版本 SW 激活时清理旧缓存并 skipWaiting / clients.claim。
   - 仅在 https 或 localhost 下注册 SW；file:// 打开时保持普通网站行为。
   - 部署流水线打包 manifest、sw.js、icons/ 与既有资源。

##### v1.4 第一批交互细节

1. 四个工具均粘贴输入后自动处理，参数变化即时重算，沿用 220ms 防抖。
2. 颜色结果使用色板 + 键值行 + 复制按钮展示；进制结果为文本输出；文本与 Mock 结果为文本输出。
3. 全部工具提供复制输出、清空、示例，并参与 URL hash 状态恢复。

##### v1.4 第一批边界与错误处理

1. 输入上限沿用 1 MiB；进制输入额外限制 100 个数字字符。
2. 颜色无法识别、进制无法解析、位运算缺少操作数、移位越界均报可读错误，不清空输入。
3. Mock 模板非法 JSON、根模板形状不符、未知占位符、参数越界报可读错误。
4. localStorage 不可用时收藏与最近使用静默降级，不影响工具使用。
5. 所有处理保留在浏览器本地，无网络请求（Service Worker 缓存同样不涉及业务数据）。

### 7.2 Base64 工具

#### 功能范围

v1 支持：

1. 文本转 Base64。
2. Base64 转文本。
3. UTF-8 安全编解码。
4. 标准 Base64 与 URL-safe Base64 切换。
5. 输出复制。

v1 不支持：

编码与解码必须使用 UTF-8 字节流，而不是直接按字符编码，确保中文、Emoji 等多字节字符不乱码。

4. 时间戳转日期时间。
5. 日期时间转时间戳。
6. 时区选择。
7. 常用格式复制。

#### 时间戳输入规则

| 输入 | 解释 |
| --- | --- |
| 10 位数字 | 秒级 Unix 时间戳 |
| 13 位数字 | 毫秒级 Unix 时间戳 |
| ISO 8601 字符串 | 解析为时间 |
| 常见日期时间字符串 | 按选定时区解析 |

- 毫秒级时间戳。

#### 时区

- v1 提供常用时区选择，并默认跟随浏览器本地时区。
- 时间显示使用明确的时区偏移，例如 `2026-11-06 21:30:00 +08:00`。
- 避免只显示本地时间而隐藏时区信息。

### 7.4 正则表达式工具

#### 功能范围

v1 支持：

1. 输入正则表达式。
2. 输入 flags，例如 `g`、`i`、`m`、`s`、`u`。
3. 输入测试文本。
4. 显示全部匹配。
5. 显示每个匹配的起止位置。
6. 显示捕获分组。
7. 匹配结果高亮。
8. 替换预览。
9. 常用正则示例。
10. 正则基础讲解，覆盖常用字符、量词、边界、分组和 flags。
11. 常用示例一键填入，包括邮箱、URL、手机号、日期和颜色值。

#### 引擎语义

v1 使用浏览器 JavaScript `RegExp`。

必须在界面上提示：

1. 不同语言的正则方言存在差异。
2. 环视、命名分组、Unicode 属性等能力以浏览器支持为准。
3. 工具结果不等价于 Java、Python 或 PCRE 的所有行为。

#### 讲解与示例

正则工具提供两组辅助学习内容：

1. **基础讲解**
   - 字符与字符类
   - 量词
   - 边界匹配
   - 分组与捕获
   - 常用 flags
2. **常用示例**
   - 匹配邮箱
   - 匹配 URL
   - 匹配中国大陆手机号
   - 匹配 ISO 日期
   - 匹配十六进制颜色值

示例必须展示表达式、测试文本和替换表达式（如适用），点击后一键填入并立即执行。

#### 性能与安全

正则回溯可能造成长时间计算。为避免阻塞页面：

1. v1 将正则匹配放入 Web Worker 或可中断子任务中执行。
2. 设置输入长度上限。
3. 设置计算超时。
4. 超时后提示表达式可能存在灾难性回溯。

### 7.5 Cron 表达式工具

#### 功能范围

v1 支持：

1. 标准五字段 Cron 校验。
2. 字段解释：

   - hour
   - day of month

3. 人类可读描述。
4. 预览未来执行时间。
5. 时区选择。
6. 常用 Cron 示例。
7. Cron 语法讲解，覆盖五字段顺序、常用符号和日期/星期联合语义。
8. 常用示例一键填入，包括固定频率、每日任务、工作日任务和月度任务。

#### v1 支持语法

优先支持：

1. `*`
2. 数字
3. `,`
4. `-`
5. `/`
6. 常见缩写，例如月份和星期的英文缩写

#### 讲解与示例

Cron 工具提供：

1. **五字段讲解**
   - minute
   - hour
   - day of month
   - month
   - day of week
2. **符号讲解**
   - `*`
   - 数字
   - `,`
   - `-`
   - `/`
3. **语义提示**
   - day of month 与 day of week 同时受限时，标准 Cron 使用“或”语义。
4. **常用示例**

4. 时区信息。

## 9. 边界与错误处理

### 9.1 通用边界

| 风险 | 策略 |
| --- | --- |
| 超大输入 | 设置默认输入上限，超限时提示并停止处理 |
| 输出过长 | 截断显示，保留复制完整结果的能力或明确提示 |
| URL 超长 | 提示用户精简内容 |
| 浏览器兼容 | 明确支持现代浏览器 |
| 处理阻塞 | JSON 与 Base64 防抖；正则与 Cron 预览使用 Worker 或分段计算 |

### 9.2 各工具错误处理

#### JSON

1. 空输入：提示“等待输入”。
2. 非法 JSON：显示错误信息、行列位置和上下文片段。
3. 输入为 JSON 以外的文本：提示校验失败。
4. 深层或超长 JSON：提示可能影响性能，并可停止实时格式化。

#### Base64

1. 解码内容不是合法 Base64：提示非法字符和位置。
2. 解码结果不是合法 UTF-8：提示无法安全转成文本。
3. URL-safe 与标准模式不匹配：提示用户切换模式。
4. 空输入：提示“等待输入”。

#### 时间戳

1. 时间戳超出安全范围：提示超出可表示范围。
2. 日期字符串无法解析：显示解析失败。
3. 时区无效：回退 UTC 或本地时区并提示。
4. 毫秒与秒自动识别错误：允许用户显式选择单位。

#### 正则

1. 表达式非法：显示浏览器错误信息。
2. flags 非法：提示支持的 flags。
3. 无匹配：明确显示“无匹配”，不视为错误。
4. 灾难性回溯：终止计算并提示风险。
5. 测试文本过长：提示截断或要求减少输入。

#### Cron

1. 字段数量错误：提示标准五字段要求。
2. 字段值超出范围：定位错误字段。
3. 语法不支持：提示 v1 支持范围。
4. 无法生成未来时间：提示表达式可能永远不触发或语法存在冲突。

## 10. 安全与隐私

1. 默认所有数据处理在浏览器本地完成。
2. 不向服务端上传输入、输出或参数。
3. 不执行用户提交的代码。
4. 不使用 `eval` 解析 JSON。
5. 所有输出使用文本渲染，禁止直接插入未转义 HTML。
6. 分享链接只包含用户显式生成的内容。
7. 本地存储仅保存界面偏好，不默认保存输入内容。
8. 正则计算放在 Web Worker 中，避免页面失去响应。

## 12. 部署设计

### 12.1 目标环境

v1 通过 GitHub Pages 部署：

1. 使用 GitHub Actions 作为部署流水线。
2. 维护者手动执行 `git push` 推送 `main` 分支到远程仓库。
3. 推送后，GitHub Actions 自动运行 `node --test`。
4. 测试通过后，工作流将 `index.html`、`assets/` 和 `.nojekyll` 打包为 Pages artifact 并部署。
5. 工作流保留 `workflow_dispatch`，用于在 GitHub Actions 页面手动重跑。
6. 不需要单独构建步骤。

### 12.2 部署要求

1. Pages Source 使用 `GitHub Actions`。
2. 仓库默认分支为 `main`。
3. 页面通过 `https://<owner>.github.io/<repo>/` 访问。
4. 应用使用相对路径加载资源和 Worker，因此兼容 Pages 子路径。
5. 分享链接基于 `window.location.href` 生成，不依赖固定域名，后续绑定自定义域名也可用。
6. 发布由维护者手动推送 `main` 触发；代理、脚本或其他自动化推送只要目标是 `main`，也会触发相同流水线。

### 12.3 部署边界

1. 不部署 Node 服务。
2. 不需要数据库或运行时密钥。
3. 不做服务端代理。
4. v1 不配置自定义域名；如后续需要，再补充 `CNAME` 与 DNS 记录说明。

## 13. 可访问性

1. 所有工具可通过键盘完成输入、切换和复制。
2. 错误提示与表单控件关联。
3. 复制成功使用文本和状态提示，不只依赖颜色。
4. 移动端触控目标不小于 44px。
5. 对比度满足 WCAG AA。
6. 深浅色主题均需可读。
