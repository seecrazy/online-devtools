# Online DevTools 开发者工具箱设计文档

## 1. 背景

开发者在日常工作中经常需要格式化 JSON、编解码 Base64、转换时间戳、调试正则表达式或解释 Cron 表达式。这些操作高频、轻量、对隐私敏感，通常不需要完整后端服务，也不应该要求用户登录或安装本地工具。

Online DevTools 的定位从早期的“在线代码运行 playground”调整为“开发者常用工具箱”。v1 聚焦五个高频工具，优先做到打开即用、结果可靠、可分享、可复制。

## 2. 目标

### v1 目标

1. 提供五类核心工具：
   - JSON 解析与格式化
   - Base64 编解码
   - 时间戳与时间转换
   - 正则表达式测试
   - Cron 表达式解析
2. 无需登录即可使用。
3. 数据处理默认在浏览器本地完成，不上传服务器。
4. 支持复制输入、输出和常用结果。
5. 支持通过 URL hash 保存当前工具状态。
6. 支持通过分享链接恢复完整输入与参数。
7. 支持桌面端与移动端基础可用布局。
8. 提供清晰、可操作的错误提示。

### v2 目标

1. 分批补齐开发者高频工具：
   - URL 编解码与解析
   - UUID 生成器
   - Hash 工具
   - HTTP 状态码速查
   - MIME Type 速查
   - HTML Entity 编解码
   - 颜色转换器
   - 进制与位运算
   - 文本处理工具
   - Mock 数据生成
2. 支持联调排查工具：
   - JWT 解析
   - 文本与 JSON Diff
   - 乱码修复与字符编码转换
3. 支持数据格式转换工具：
   - YAML ↔ JSON
   - CSV ↔ JSON
   - TOML ↔ JSON
   - XML 格式化
   - SQL 格式化
   - Markdown / HTML 转换
4. 支持本地收藏与最近使用记录。
5. 支持 PWA 离线使用。
6. 支持更多 JSON 树形查看、JSONPath、Diff 能力。
7. 支持 Quartz Cron 或更完整的 Cron 方言。

## 3. 非目标

以下内容明确不在 v1 范围内：

1. 不做在线代码运行环境。
2. 不做通用在线 IDE。
3. 不做实时协作。
4. 不做账号、团队、权限、订阅和付费。
5. 不做服务端数据存储。
6. 不承诺支持所有正则引擎方言；v1 以浏览器 JavaScript RegExp 语义为准。
7. 不承诺支持所有 Cron 方言；v1 优先支持标准五字段 Cron。

## 4. 目标用户与核心场景

### 用户

- 后端开发者：排查接口 JSON、调试 Cron 任务、转换时间戳。
- 前端开发者：处理 Base64、调试正则、格式化 JSON。
- 测试与运维人员：检查正则匹配、解释定时任务表达式。
- 技术写作者：生成可分享的示例和结果。

### 核心场景

1. **JSON 排查**：粘贴接口返回的 JSON，快速格式化并定位语法错误。
2. **编解码转换**：处理 URL、Header、Token 中的 Base64 内容。
3. **时间换算**：将日志中的 Unix 时间戳转换为可读时间，或将本地时间转换为时间戳。
4. **正则调试**：输入表达式与测试文本，查看匹配结果和分组。
5. **Cron 排查**：输入 Cron 表达式，查看执行含义和未来执行时间。
6. **状态分享**：把某个工具的输入和参数放入链接，发给同事继续排查。

## 5. 用户流程

### 5.1 首次使用

```text
打开首页
  → 看到工具入口
  → 选择目标工具
  → 输入内容并设置参数
  → 应用自动或手动执行
  → 查看结果
  → 复制结果或分享链接
```

### 5.2 打开分享链接

```text
点击分享链接
  → 应用恢复工具类型、输入内容、参数和输出区域状态
  → 自动执行解析或转换
  → 用户查看结果
```

### 5.3 错误路径

```text
输入无效 JSON / Base64 / 时间 / 正则 / Cron
  → 保持原始输入
  → 显示明确错误原因
  → 提供可操作建议
  → 不清空用户输入
```

## 6. 信息架构与导航

### 6.1 页面结构

```text
┌──────────────────────────────────────────────┐
│ Logo / 工具搜索 / 主题切换 / 帮助入口          │
├────────────┬─────────────────────────────────┤
│            │ 工具标题与简介                   │
│ 工具导航    ├─────────────────────────────────┤
│            │ 输入区 / 参数区                  │
│ JSON       ├─────────────────────────────────┤
│ Base64     │ 输出区 / 错误提示                 │
│ 时间戳      ├─────────────────────────────────┤
│ 正则        │ 操作栏：复制 / 清空 / 示例 / 分享 │
│ Cron       │                                  │
└────────────┴─────────────────────────────────┘
```

### 6.2 响应式布局

- 桌面端：左侧固定工具导航，右侧为工作区。
- 平板端：工具导航可折叠。
- 移动端：顶部工具下拉或抽屉导航，输入输出上下排列。

### 6.3 关键通用交互

1. **自动执行**
   - JSON、Base64、时间戳工具在输入变化后自动处理。
   - 正则与 Cron 输入变化后自动校验并更新结果。
   - 对较大输入使用防抖，避免频繁计算阻塞界面。

2. **复制**
   - 输入区、输出区均提供复制按钮。
   - 时间戳工具支持复制秒级时间戳、毫秒级时间戳和格式化时间。
   - 复制成功后提供短暂状态反馈。

3. **清空与示例**
   - 每个工具提供“清空”。
   - 每个工具提供至少一个可运行的示例。

4. **分享**
   - 点击“分享”生成当前工具状态 URL。
   - 状态放在 URL hash 中。
   - URL 超过安全长度时提示用户精简内容。

5. **主题**
   - 支持系统深浅色模式。
   - 用户手动选择后写入本地偏好，但不参与分享链接。

## 7. 工具设计

### 7.0 扩展工具总体设计

后续工具按四个层级组织：

1. **导航分组**
   - 常用转换：JSON、Base64、URL、时间戳
   - 校验调试：正则、Cron、Hash、JWT、Diff
   - 速查手册：HTTP、MIME
   - 数据处理：文本、颜色、进制、Mock、格式转换
2. **通用工作台**
   - 输入区、参数区、输出区复用现有模式。
   - 速查类工具使用搜索 + 表格布局。
   - 转换类工具使用输入输出双栏布局。
3. **分批交付**
   - v1.1：高频通用工具
   - v1.2：联调排查工具
   - v1.3：数据格式转换
   - v1.4：高级体验与离线能力
4. **质量边界**
   - 每批工具必须包含设计、实现、自动化测试和验收记录。
   - 新工具不改变“浏览器本地处理、不上传数据”的隐私边界。

#### v1.1 工具范围

1. **URL 编解码**
   - URL encode / decode
   - Base64URL 可与标准 URL 编码区分
   - Query 参数解析与组装
   - URL 结构解析
2. **UUID 生成器**
   - UUID v4 批量生成
   - 大小写切换
   - 连字符开关
   - UUID 校验
3. **Hash 工具**
   - SHA-1 / SHA-256 / SHA-384 / SHA-512
   - 输入文本
   - 输出小写 / 大写
   - 浏览器 `crypto.subtle` 本地计算
4. **HTTP 状态码速查**
   - 1xx / 2xx / 3xx / 4xx / 5xx
   - 搜索
   - 含义、常见场景与缓存/重试语义
5. **MIME Type 速查**
   - 常见扩展名与 MIME 映射
   - 搜索

#### v1.2 工具范围

1. **JWT 解析器**
   - Header / Payload / Signature 展示
   - Base64URL 解码
   - `iat`、`exp`、`nbf` 解释
   - 过期状态提示
   - 不验证签名
2. **Diff 工具**
   - 文本行级 Diff
   - JSON 格式化后 Diff
   - 新增、删除、修改标记
3. **乱码修复与字符编码**
   - Hex ↔ Text
   - 常见乱码说明
   - UTF-8 / Latin-1 转换

#### v1.3 工具范围

1. **YAML ↔ JSON**
2. **CSV ↔ JSON**
3. **TOML ↔ JSON**
4. **XML 校验与格式化**
5. **SQL 基础格式化**
6. **Markdown / HTML 转换**

#### v1.4 工具范围

1. **颜色转换器**
   - HEX / RGB / HSL
   - 亮度与对比度
2. **进制与位运算**
   - 二进制 / 八进制 / 十进制 / 十六进制
   - 与、或、异或、非、移位
3. **文本处理工具**
   - 命名风格转换
   - 行排序、去重、修剪
   - LF / CRLF 转换
4. **Mock 数据生成**
   - 姓名、邮箱、手机号、时间、数字、UUID、JSON 模板

### 7.1 JSON 工具

#### 功能范围

v1 支持：

1. JSON 校验。
2. JSON 格式化。
3. JSON 压缩。
4. 缩进选择：2 空格、4 空格、Tab。
5. 错误行列定位与可读错误信息。
6. 结果复制。

v2 可扩展：

1. JSON 树形查看。
2. JSONPath 查询。
3. 排序 key。
4. JSON 与 YAML、CSV 互转。
5. JSON Diff。

#### 交互

```text
输入 JSON
  → 自动校验
  → 合法：格式化结果出现在输出区
  → 非法：错误面板显示原因、行号与列号
```

### 7.2 Base64 工具

#### 功能范围

v1 支持：

1. 文本转 Base64。
2. Base64 转文本。
3. UTF-8 安全编解码。
4. 标准 Base64 与 URL-safe Base64 切换。
5. 输出复制。

v1 不支持：

1. 大文件上传。
2. 二进制文件编码。
3. 图片预览。

#### 交互

```text
选择编码 / 解码
  → 输入文本
  → 自动输出结果
  → 可切换 URL-safe 模式
```

#### Unicode 处理

编码与解码必须使用 UTF-8 字节流，而不是直接按字符编码，确保中文、Emoji 等多字节字符不乱码。

### 7.3 时间戳与时间转换工具

#### 功能范围

v1 支持：

1. 显示当前秒级 Unix 时间戳。
2. 显示当前毫秒级 Unix 时间戳。
3. 显示当前 ISO 8601 时间。
4. 时间戳转日期时间。
5. 日期时间转时间戳。
6. 时区选择。
7. 常用格式复制。

#### 时间戳输入规则

| 输入 | 解释 |
| --- | --- |
| 10 位数字 | 秒级 Unix 时间戳 |
| 13 位数字 | 毫秒级 Unix 时间戳 |
| ISO 8601 字符串 | 解析为时间 |
| 常见日期时间字符串 | 按选定时区解析 |

自动识别规则必须显示在界面上，避免用户误解。

#### 输出

- 秒级时间戳。
- 毫秒级时间戳。
- ISO 8601。
- 选定时区的可读日期时间。
- 星期、年内天数等辅助信息可放 v2。

#### 时区

- v1 提供常用时区选择，并默认跟随浏览器本地时区。
- 时间显示使用明确的时区偏移，例如 `2026-11-06 21:30:00 +08:00`。
- 避免只显示本地时间而隐藏时区信息。

### 7.4 正则表达式工具

#### 功能范围

v1 支持：

1. 输入正则表达式。
2. 输入 flags，例如 `g`、`i`、`m`、`s`、`u`。
3. 输入测试文本。
4. 显示全部匹配。
5. 显示每个匹配的起止位置。
6. 显示捕获分组。
7. 匹配结果高亮。
8. 替换预览。
9. 常用正则示例。
10. 正则基础讲解，覆盖常用字符、量词、边界、分组和 flags。
11. 常用示例一键填入，包括邮箱、URL、手机号、日期和颜色值。

#### 引擎语义

v1 使用浏览器 JavaScript `RegExp`。

必须在界面上提示：

1. 不同语言的正则方言存在差异。
2. 环视、命名分组、Unicode 属性等能力以浏览器支持为准。
3. 工具结果不等价于 Java、Python 或 PCRE 的所有行为。

#### 讲解与示例

正则工具提供两组辅助学习内容：

1. **基础讲解**
   - 字符与字符类
   - 量词
   - 边界匹配
   - 分组与捕获
   - 常用 flags
2. **常用示例**
   - 匹配邮箱
   - 匹配 URL
   - 匹配中国大陆手机号
   - 匹配 ISO 日期
   - 匹配十六进制颜色值

示例必须展示表达式、测试文本和替换表达式（如适用），点击后一键填入并立即执行。

#### 性能与安全

正则回溯可能造成长时间计算。为避免阻塞页面：

1. v1 将正则匹配放入 Web Worker 或可中断子任务中执行。
2. 设置输入长度上限。
3. 设置计算超时。
4. 超时后提示表达式可能存在灾难性回溯。

### 7.5 Cron 表达式工具

#### 功能范围

v1 支持：

1. 标准五字段 Cron 校验。
2. 字段解释：
   - minute
   - hour
   - day of month
   - month
   - day of week
3. 人类可读描述。
4. 预览未来执行时间。
5. 时区选择。
6. 常用 Cron 示例。
7. Cron 语法讲解，覆盖五字段顺序、常用符号和日期/星期联合语义。
8. 常用示例一键填入，包括固定频率、每日任务、工作日任务和月度任务。

#### v1 支持语法

优先支持：

1. `*`
2. 数字
3. `,`
4. `-`
5. `/`
6. 常见缩写，例如月份和星期的英文缩写

#### 讲解与示例

Cron 工具提供：

1. **五字段讲解**
   - minute
   - hour
   - day of month
   - month
   - day of week
2. **符号讲解**
   - `*`
   - 数字
   - `,`
   - `-`
   - `/`
3. **语义提示**
   - day of month 与 day of week 同时受限时，标准 Cron 使用“或”语义。
4. **常用示例**
   - 每分钟
   - 每 5 分钟
   - 每小时
   - 每天 09:00
   - 工作日 09:00
   - 每月 1 日 00:00
   - 每季度第一天

示例点击后一键填入，并立即展示字段解释和未来执行时间。

v1 暂不支持：

1. Quartz 六字段或七字段表达式。
2. `@yearly`、`@monthly` 等宏。
3. 复杂方言扩展。

#### 输出

1. 表达式是否合法。
2. 每个字段的规范化解释。
3. 未来 5 到 10 次执行时间。
4. 时区信息。
5. 错误字段定位。

## 8. 数据与状态模型

### 8.1 客户端状态

```text
ToolSession
  toolId: "json" | "base64" | "timestamp" | "regex" | "cron"
  input: string
  params: ToolParams
  output: string | null
  status: ToolStatus
  error: ToolError | null
  updatedAt: number
```

```text
ToolStatus
  "idle" | "processing" | "success" | "error" | "timeout" | "truncated"
```

### 8.2 各工具参数模型

```text
JsonParams
  mode: "format" | "minify"
  indent: 2 | 4 | "tab"
```

```text
Base64Params
  mode: "encode" | "decode"
  urlSafe: boolean
```

```text
TimestampParams
  mode: "timestampToDate" | "dateToTimestamp"
  timezone: string
  timestampUnit: "seconds" | "milliseconds" | "auto"
```

```text
RegexParams
  pattern: string
  flags: string
  testText: string
  replaceText: string | null
```

```text
CronParams
  expression: string
  timezone: string
  previewCount: number
```

### 8.3 URL 分享

v1 使用无状态 URL 分享：

```text
https://example.com/#/tool/<toolId>?state=<encoded-state>
```

编码内容包含：

1. schema version
2. toolId
3. input
4. params
5. 是否自动执行输出

不包含：

1. 用户主题偏好。
2. 本地收藏。
3. 最近使用记录。
4. 任何账号信息。

### 8.4 本地状态

主题偏好、最近工具选择、折叠状态可存入 `localStorage`。

输入内容默认不写入 `localStorage`，除非 v2 明确提供“保存草稿”功能并获得用户确认。

## 9. 边界与错误处理

### 9.1 通用边界

| 风险 | 策略 |
| --- | --- |
| 超大输入 | 设置默认输入上限，超限时提示并停止处理 |
| 输出过长 | 截断显示，保留复制完整结果的能力或明确提示 |
| URL 超长 | 提示用户精简内容 |
| 浏览器兼容 | 明确支持现代浏览器 |
| 处理阻塞 | JSON 与 Base64 防抖；正则与 Cron 预览使用 Worker 或分段计算 |

### 9.2 各工具错误处理

#### JSON

1. 空输入：提示“等待输入”。
2. 非法 JSON：显示错误信息、行列位置和上下文片段。
3. 输入为 JSON 以外的文本：提示校验失败。
4. 深层或超长 JSON：提示可能影响性能，并可停止实时格式化。

#### Base64

1. 解码内容不是合法 Base64：提示非法字符和位置。
2. 解码结果不是合法 UTF-8：提示无法安全转成文本。
3. URL-safe 与标准模式不匹配：提示用户切换模式。
4. 空输入：提示“等待输入”。

#### 时间戳

1. 时间戳超出安全范围：提示超出可表示范围。
2. 日期字符串无法解析：显示解析失败。
3. 时区无效：回退 UTC 或本地时区并提示。
4. 毫秒与秒自动识别错误：允许用户显式选择单位。

#### 正则

1. 表达式非法：显示浏览器错误信息。
2. flags 非法：提示支持的 flags。
3. 无匹配：明确显示“无匹配”，不视为错误。
4. 灾难性回溯：终止计算并提示风险。
5. 测试文本过长：提示截断或要求减少输入。

#### Cron

1. 字段数量错误：提示标准五字段要求。
2. 字段值超出范围：定位错误字段。
3. 语法不支持：提示 v1 支持范围。
4. 无法生成未来时间：提示表达式可能永远不触发或语法存在冲突。

## 10. 安全与隐私

1. 默认所有数据处理在浏览器本地完成。
2. 不向服务端上传输入、输出或参数。
3. 不执行用户提交的代码。
4. 不使用 `eval` 解析 JSON。
5. 所有输出使用文本渲染，禁止直接插入未转义 HTML。
6. 分享链接只包含用户显式生成的内容。
7. 本地存储仅保存界面偏好，不默认保存输入内容。
8. 正则计算放在 Web Worker 中，避免页面失去响应。

## 12. 部署设计

### 12.1 目标环境

v1 通过 GitHub Pages 部署：

1. 使用 GitHub Actions 作为部署流水线。
2. 维护者手动执行 `git push` 推送 `main` 分支到远程仓库。
3. 推送后，GitHub Actions 自动运行 `node --test`。
4. 测试通过后，工作流将 `index.html`、`assets/` 和 `.nojekyll` 打包为 Pages artifact 并部署。
5. 工作流保留 `workflow_dispatch`，用于在 GitHub Actions 页面手动重跑。
6. 不需要单独构建步骤。

### 12.2 部署要求

1. Pages Source 使用 `GitHub Actions`。
2. 仓库默认分支为 `main`。
3. 页面通过 `https://<owner>.github.io/<repo>/` 访问。
4. 应用使用相对路径加载资源和 Worker，因此兼容 Pages 子路径。
5. 分享链接基于 `window.location.href` 生成，不依赖固定域名，后续绑定自定义域名也可用。
6. 发布由维护者手动推送 `main` 触发；代理、脚本或其他自动化推送只要目标是 `main`，也会触发相同流水线。

### 12.3 部署边界

1. 不部署 Node 服务。
2. 不需要数据库或运行时密钥。
3. 不做服务端代理。
4. v1 不配置自定义域名；如后续需要，再补充 `CNAME` 与 DNS 记录说明。

## 13. 可访问性

1. 所有工具可通过键盘完成输入、切换和复制。
2. 错误提示与表单控件关联。
3. 复制成功使用文本和状态提示，不只依赖颜色。
4. 移动端触控目标不小于 44px。
5. 对比度满足 WCAG AA。
6. 深浅色主题均需可读。
